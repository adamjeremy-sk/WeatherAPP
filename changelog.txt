Changelog 0.8.0VC27 - 2026/10/30
---------------
* Security & Release Hardening:
* Hardened the CAP-CP XML parser against XXE and OOM attacks by disabling DTD processing and enforcing a 5MB byte ceiling.
* Restricted in-app WebView navigation strictly to the `weatherapplibre.ca` allowlist; external links now launch in the system browser.
* Gated the test-alert injection menu behind `BuildConfig.DEBUG` to prevent end-user access in production builds.
* Replaced fragile string-matching for test alerts with a typed `isTest` boolean in the alert banner manager.
* Added a fail-fast guard for the MeteoGate API key to prevent silent EU alert fetch failures.
* Protected 4 Gson-serialized almanac classes with `@Keep` annotations to ensure survival through R8 minification.
* Documented the intentional release signing fallback (debug key) in the build script to prevent future CI/CD confusion.
* Forecast & Precipitation Enhancements:
* Added daily precipitation totals (rain, snow, sum) and maximum probability to the 7-day expanded forecast details.
* Reworked precipitation UI placement: moved the 7-day collapsed pill to expanded details and introduced a new, perfectly aligned hourly precipitation pill using a ConstraintLayout Barrier.
* Widget & Alert Pipeline Reliability:
* Added strict AppWidgetManager ID ownership and tab-index bounds checking to all widget receivers to reject malformed intents.
* Corrected the legacy 2x2 widget receiver and manifest metadata to accurately reflect its true 2x1 layout dimensions.
* Wired test alert injection paths (ECCC and EU harnesses) into the Alert Log repository for accurate diagnostic history.
* Dynamically generated bounding boxes for EU test fixtures to ensure they correctly match any target European location tab.
* Applied WorkManager constraints (`NetworkType.CONNECTED`, `BatteryNotLow`) to the periodic `WidgetSyncWorker` to prevent unnecessary background wakeups and battery drain.
* Lifecycle, Concurrency & Memory Hygiene:
* Implemented a process-wide `synchronized` lock in `LocationPreferences` to eliminate race conditions where the main app and widget sync workers could overwrite each other's saved locations.
* Wrapped `AlertLogRepository` read-modify-write operations in a coroutine `Mutex` to prevent concurrent alert history corruption.
* Capped the persistent forecast disk cache at 50 entries with automatic FIFO eviction of the oldest data to prevent unbounded SharedPreferences growth.
* Added explicit `cleanup()` lifecycle methods to `SettingsDialogManager`, `WeatherDisplayManager`, and `AstronomyDisplayManager` to prevent `WindowManager` leaks and handler runaways on Activity destruction.
* Hard-capped the volume-key rapid-cycle date loop at 10 seconds and added an `onPause` lifecycle observer to guarantee termination if the app is backgrounded while a key is held.
* Fixed a UX quirk where the live header clock would stall during network fetches; the update heartbeat now survives timezone resolution delays.
* Purged dead code: deleted obsolete name-keyed alert dismissal functions and two orphaned layout XML files.
* Forecast Pipeline & Network Optimization:
* Converted all blocking network calls (`call.execute()`) to non-blocking, coroutine-friendly `call.enqueue()` wrappers across the weather repository, alert providers, and settings HTML fetches, freeing up IO threads and improving cancellation behavior.
* Implemented in-flight network request deduplication in `WeatherRepository` using a `ConcurrentHashMap` of `Deferred` values to prevent duplicate API calls when the app and widget sync simultaneously.
* Verified and confirmed all display-layer array indexing is safely bounds-guarded and null-safe against truncated provider responses.
* Edge Case & Math Hardening:
* Eliminated a redundant double-save and double-fetch cycle during location tab initialization.
* Synchronized the system night-mode state immediately when switching boutique themes, preventing stale `values-night` resource resolution until the next app launch.
* Added a `1e-9` epsilon tolerance to the alert polygon edge-matching algorithm, ensuring locations exactly on a polygon boundary (or within floating-point ULP noise) are correctly included, matching the inclusive semantics of circular alert zones.
* Testing & Pipeline Hardening:
* Expanded the automated test suite from 178 to 216 passing tests, achieving comprehensive coverage of the forecast, widget, and alert delivery pipelines.
* Added extensive regression tests for alert polygon boundary math, consent gates, provider failure isolation, and cache corruption recovery.
